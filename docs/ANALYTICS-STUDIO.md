# Analytics workspace

The Analytics workspace has three entry points: Reports, Data sources and Prepare data. Existing dashboard URLs and saved definitions are retained.

- Reports can be searched by name or description, sorted by name or most recently updated, and viewed as cards or a table. Create report opens a blank report. Card previews identify the saved visual types; they do not invent sample figures.
- Data sources separates connected sources, connector selection and load history. Connected file sources expose their field names, original headings and types. CSV and Excel connector choices filter the available server-folder files; existing preview, type mapping, loading and nightly refresh flows are reused. Books/CRM and report-email collection use their existing services.
- Microsoft SQL Server, PostgreSQL and MySQL connectors (decisions 602-605) follow the Power BI and Looker Studio flow: choose the database type, enter the server, port (or SQL Server instance), database, user, password and encryption, test the connection, choose a table or view or write one SELECT query, preview the columns and first rows, confirm each column's type, then load into the organisation's own DuckDB copy. Database sources reload nightly and on demand, appear in Load history like files, and can be edited (the table name stays). Connections are listed per database type, only for admins and owners; a connection used by a source can't be removed.
- The Google Analytics connector (decisions 606-609) signs in with Google through the organisation's Google app, lists the GA4 properties the account can see, and loads five daily tables (`google_analytics_daily`, `_traffic`, `_pages`, `_countries`, `_devices`) with Refresh now, nightly reloads, load history and Disconnect. Connected, it appears in Connected sources too. Its help lists what an admin enables in Google Cloud, and that Google ends sign-ins after 7 days while the app is in Testing. A Website report template uses its tables.
- The chart editor places a searchable field catalogue beside a live preview and a properties panel. Choose a visual, source, dimensions, measures, filters and width, then add it to the report or apply changes. Saving is disabled while a preview is pending or invalid. Report-level save/view and delete wait until the chart editor is closed, so they cannot silently abandon an unfinished chart.
- Report themes (#376 phase 1, decisions 668-671) follow Power BI's report themes and Looker Studio's theme panel. Theme, in the report toolbar while editing, lists the six built-in themes and the organisation's own; the theme editor (colours for light and dark, fonts, text sizes, card style) shows a live preview and the colour checks, and themes import and export as JSON. The theme is scoped to the report's tiles and the chart preview; the rest of Tohyee, including pinned tiles, keeps the Tohyee look. "Set as default for <chart type> in this report" and Copy format / Paste format follow Power BI's visual defaults and format painter.
- Each chart's Format section (#376 phase 1, decisions 672-673) follows Power BI's format pane: title and card, colours (any hex per value or group, with Reset to the theme and colour warnings), data labels, legend, axes, gridlines and plot area, reference lines, trend and forecast, tooltip, and column and line options, grouped in collapsible sections. A colour chosen on a chart is drawn as a worked-out dark version in dark mode.
- Key figures (#376 phase 1, decision 674) follow Power BI's card and new card visual: number size, colour, alignment, weight and name position; colour by rules or by the comparison; an arrow or dot; trend style and colour; and several numbers in one card.
- Tables and pivots (#376 phase 1, decision 675) have Table style and Conditional formatting sections, following Power BI: colour scales, rules or a field's colours for backgrounds and text, data bars, icons, header and band colours, gridlines, text size, column width, wrapping, totals and subtotals. Charts have Colour rules.
- More visuals (#376 phase 2, decisions 676-677): waterfall, funnel, gauge and bullet chart, following Power BI's visuals of the same names. The waterfall's running totals and total bar are worked out exactly in decimals (`waterfallSteps` in `src/lib/analytics/chart-visuals.ts`); a gauge shows one total (no grouping) and a bullet chart can show one total or one bar per group; both take an optional second value as the target. Each has its own section in the Format panel (Waterfall, Funnel, Gauge, Bullet chart) and uses the shared sections that apply to it.
- Scatter and bubble, histogram and box plot (#376 phase 2, decisions 678-679), as in Power BI's scatter chart and Excel's histogram and box and whisker charts. Bins and quartiles are worked out exactly in decimals (`histogramBins`, `boxStats` in `src/lib/analytics/chart-distributions.ts`). A tile can now have a second grouping inside the first (`breakdown` in the tile's query, returned as the `breakdown` column); for now only box plots use it ("Each box is made of"), and the server refuses it on other chart types and with last-year comparisons.
- Treemap, heat map, calendar heat map and Sankey (#376 phase 2, decision 680), as Power BI's treemap and the ECharts heat map, calendar and Sankey series. They use the second grouping (decision 679): optional for a treemap, required for a heat map ("Down the side") and a Sankey ("Flows to"); a calendar heat map is grouped by a date by day. Cell, box and flow totals are added exactly (`src/lib/analytics/chart-relationships.ts`). No external map or tile service is involved.
- Values and joins (#387, decisions 693-696, examples MD1-MD6). Each value in the chart editor has a folded "What <value> means" (what one row is, how it's worked out, unit, movement or balance, date, blanks and zero, totals), worked out from the definition, and "Currency and balances" (the column naming each row's currency; "each row is a balance on its date", for each account or the like). Totals rows work calculated values, averages, smallest, largest and distinct counts out from all the rows. Amounts in more than one currency are left blank where they'd mix, with a note. Tiles read one table; the only join is a shaped table's Merge, which is checked on the data before each preview and rebuild and refused when it would repeat rows or numbers. Shopify and WooCommerce orders reach Analytics only as their invoices and journals.
- Sharing is opened explicitly from the report toolbar. Report viewers stay in viewing mode even with `?edit=1` and do not request source schemas.

Direct Google Sheets and BigQuery connections, a free-position drag-and-drop canvas and multi-page reports are not implemented. Google Analytics is connected directly (above); it has been tested against canned Google responses, not a real GA4 property. There is nothing for Looker Studio: Tohyee's own reports are the place to report on these sources. The source picker says which connections are available. The current report model retains half/full-width tiles, ordering, dates, slicers, pivots and sharing.

## Database sources: read only

Tohyee only reads from an external database. A typed query must be a single SELECT (or WITH ... SELECT); comments are removed before it's checked and sent, and words that change data (INSERT, UPDATE, DELETE, INTO, EXEC, SET, ...) or functions that write, lock or read the server's files are refused outside quotes. The query then runs inside Tohyee's own outer SELECT, which also applies the row limit; in PostgreSQL the session and each transaction are read only, and in MySQL each read is a `START TRANSACTION READ ONLY` in a read-only session. SQL Server has no read-only session, so the screens ask for a login with read rights only (such as `db_datareader`). Every screen that adds a connection recommends a read-only user.

Connections are made from the Tohyee server, so databases on the local network work. Only admins and owners can add, change, test or see connections. MySQL servers can't ask Tohyee for local files, and a SQL Server that redirects the connection to another server is refused. Connection failures are reported as plain messages (wrong password, no such database, nothing answering, certificate couldn't be checked) without the driver's own text; a query's error shows the database's first line about it.

## Validation

Unit coverage checks connector availability, navigation permissions and forced edit URLs for report viewers. Browser checks against mocked API responses exercise report search/list views, source field inspection, Excel file filtering, load history, live chart editing and saving, report-viewer schema restrictions, and phone-width layouts. These checks do not establish live external service connectivity or database integration; the existing PostgreSQL integration suite requires `TEST_DATABASE_URL`.

Database sources: `tests/integration/analytics-databases.test.ts` connects to a real PostgreSQL (a made-up database and read-only user created and dropped by the test) and checks permissions, saved-password handling, previews, typed-query refusals, the read-only transaction, exact loading into DuckDB, row limits and the nightly reload. MySQL and SQL Server are covered only with stand-in drivers (`tests/unit/analytics-database-drivers.test.ts`), which check what Tohyee sends them, not that a real server accepts it; neither has been tried against a real server yet.
